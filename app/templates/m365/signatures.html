Signature templates

Manage tenant-scoped HTML and plain-text signature templates, preview them against staff data, publish them, then deploy published templates to Exchange Online mailboxes. Publishing alone does not change any mailbox; use Deploy to apply a signature.

Lifecycle: Draft templates are editable but inactive. Published means available for MyPortal use. A published template becomes scheduled or active according to its dates in {{ schedule_timezone }}. Outlook deployment: choose Deploy on a published template to apply it to selected mailboxes through Exchange Online. Deployment is a one-off push; redeploy after editing a template.

How deployment works

Deploy renders the template for each selected mailbox's staff record and applies it with the Exchange Online Set-MailboxMessageConfiguration cmdlet. This needs the Exchange.ManageAsApp permission and the Exchange Administrator role.

  • HTML and TXT variants are stored separately so administrators can publish rich and plain-text versions independently.
  • Preview uses live staff, company, custom-variable, and automation-token data before publication.
  • Deployed signatures are used by Outlook on the web and the new Outlook. Classic Outlook for Windows keeps signatures on each device; enable Classic Outlook sync above so the MyPortal tray agent keeps them up to date. Outlook for Mac is not managed.
  • Exchange ignores deployed signatures while roaming signatures are active, so Deploy only works with Exchange push. With Outlook add-in there is nothing to deploy: the add-in fetches each person's current signature whenever they start a message.
  • Deploying replaces each selected mailbox's current signature. Outlook on the web and the new Outlook hold one MyPortal signature per mailbox, so additional signatures reach users through Classic Outlook sync.
  • Use When it's used on a signature to target staff by name, job title, department, site or custom field, and to make it a primary or additional signature.
