# Per-company Microsoft 365 SSO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users of SSO-enabled companies sign in to MyPortal with their Office 365 account, auto-linking by verified email and letting admins link/unlink identities and require Microsoft sign-in per company.

**Architecture:** A shared multi-tenant public PKCE client signs users in through the `/organizations` authority with `openid profile email`. The existing `/m365/callback` recognises a new SSO state envelope and hands off to `app/services/sso_login.py`, which maps the ID token's `tid` to SSO-enabled companies and the `(tid, oid)` pair to a `user_sso_identities` row. `app/services/sso_policy.py` owns every mode/permission decision, so routes stay thin.

**Tech Stack:** Python 3.11, FastAPI, async MySQL/SQLite via `app.core.database.db`, PyJWT (already used by `validate_microsoft_id_token`), Jinja2, vanilla JS, pytest + pytest-asyncio.

**Spec:** `docs/superpowers/specs/2026-10-30-m365-sso-design.md`

## Global Constraints

- Provider value is the literal `m365`; `sso_mode` values are exactly `off`, `optional`, `required`; default `off`.
- `linked_via` values are exactly `auto`, `admin`.
- `authentication_method="m365_sso"`; `mfa_satisfied_by` is `"microsoft"` or `"myportal_totp"`.
- Audit actions: `auth.sso.link`, `auth.sso.unlink`, `auth.sso.fail`, `company.sso_mode.update`, plus existing `auth.login.succeed`.
- Failure reasons: `no_link`, `company_mismatch`, `account_disabled`, `tenant_not_enabled`, `password_login_refused`.
- Authorize URL: `https://login.microsoftonline.com/organizations/oauth2/v2.0/authorize`; token URL: `https://login.microsoftonline.com/organizations/oauth2/v2.0/token`; scope `openid profile email`; `prompt=select_account`; `code_challenge_method=S256`; `response_mode=query`.
- SSO transaction TTL 600 s (existing `m365_oauth_transactions.TTL_SECONDS`); pending-TOTP window 300 s; binding cookies HttpOnly, `SameSite=Lax`, `Secure` when the request is secure, path `/`.
- Generic failure copy: `No MyPortal account is linked to this Microsoft account. Contact your administrator.`
- Required-mode copy: `Your organisation requires Microsoft sign-in.`
- Super admins are never refused password/passkey login by `required` mode.
- Every SQL statement parameterised (`%s`), no f-string/`.format` SQL (Bandit B608); all timestamps UTC.
- Migration created via `/new-migration` with the `-- phase: expand` header; change log via `/changelog-entry`.
- `app/features/companies/__init__.py` `PACK.version` bumped `1.2.0` → `1.3.0` (new functionality).

## Review Focus

1. **`next` open redirect** — `/auth/microsoft/start?next=https://evil.example` must land on `/` after sign-in, never off-site (test in Task 4).
2. **Email claim variations** — mixed case, surrounding whitespace, or a token with no `email` claim (only `preferred_username`) must still auto-link the single matching user (test in Task 3).
3. **Tenant shared by several companies** — when one tenant maps to companies A and B and the email matches one user in A and one in B, nobody is auto-linked (test in Task 3).
4. **Already signed in as someone else** — completing Microsoft sign-in while another user's session cookie is present must create a session for the Microsoft user, not reuse the old one (test in Task 4).
5. **State envelope confusion** — a transaction with `flow="sso_login"` arriving through the session-bound `{"transaction_id": …}` envelope must be rejected, and vice versa (test in Task 4).

- Produces:
  - `PROVIDER = "m365"`; `SCOPE = "openid profile email"`; `GENERIC_FAILURE` (copy from Global Constraints).
  - `@dataclass(frozen=True) class StartResult: authorize_url: str; state_transaction_id: str; binding: str`
  - `async start(*, redirect_uri: str, login_hint: str | None, next_path: str | None) -> StartResult` — creates the transaction with `flow="sso_login"`, `code_verifier`, `nonce`, `client_id`, `redirect_uri`, `binding_hash` (`hashlib.sha256(binding.encode()).hexdigest()`), `next_path`; `binding = secrets.token_urlsafe(32)`, `nonce = secrets.token_urlsafe(16)`.
  - `def binding_matches(transaction: dict, binding: str | None) -> bool` — `hmac.compare_digest`.
  - `@dataclass(frozen=True) class Outcome: user: dict | None; identity: dict | None; failure: str | None; mfa_satisfied: bool; message: str`
  - `async resolve(claims: dict, *, request: Request | None) -> Outcome` — implements spec *Resolve the user* steps; on auto-link calls `create(..., linked_via="auto", linked_by_user_id=None)` and audits `auth.sso.link`; audits `auth.sso.fail` only when a user was identified.
  - `def mfa_satisfied(claims: dict) -> bool` — `"mfa" in claims.get("amr", [])` (accepts list or space-separated string).
  - `async redeem_code(transaction: dict, code: str) -> dict` — POSTs to the token URL with `client_id`, `grant_type=authorization_code`, `code`, `redirect_uri`, `code_verifier`, `scope`; returns claims after `validate_microsoft_id_token` and a nonce check; raises `m365_service.M365Error` on any failure. Uses `monitored_client(httpx.AsyncClient, timeout=15)` as `validate_microsoft_id_token` does.
