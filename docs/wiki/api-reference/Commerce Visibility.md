# Quote, order and invoice visibility

Company roles use **None**, **Mine** or **All** for Quotes, Orders and Invoices.

| Setting | Visibility |
| --- | --- |
| None | No access to the section or its authenticated API endpoints. |
| Mine | Records created by or assigned to the signed-in user. Orders use the purchaser; quotes use the creator or assigned user; invoices use the creator or assigned user. |
| All | All records within the authorized company. |

Super administrators, company administrators and technician roles retain their
company access. All does not grant access to another company's records or grant
additional administrative actions. Existing boolean company permissions preserve
their previous company-wide access until a role defines a visibility setting.

The Roles editor shows None/Mine/All. Role API payloads accept `none`, `mine`
and `all` for `menu.quotes`, `menu.orders` and `menu.invoices`. For compatibility,
stored and returned levels remain `none`, `read` (Mine) and `write` (All).

The visibility setting applies to these authenticated read endpoints:

- `GET /api/quotes?companyId=7` and `GET /api/quotes/{quoteNumber}?companyId=7`
- `GET /api/orders?companyId=7` and `GET /api/orders/{orderNumber}?companyId=7`
- `GET /api/invoices?companyId=7` and `GET /api/invoices/{invoiceId}`

Lists return only visible records. None returns HTTP 403. Under Mine, direct
requests for another user's record return HTTP 404. Portal lists, counts,
invoice totals, quote PDF downloads and loading quotes into the cart follow
the same visibility setting. Existing public quote magic links continue to
authorize access using their bearer token.

## Invoice ownership and assignment

`POST /api/invoices` accepts an optional `assignedUserId`. The server records
`createdBy` from the authenticated user; clients cannot choose the creator.
Invoices created when placing an order also record the purchaser as creator.
Invoices generated by a system job have no creator. Historical invoices remain
unowned until assigned, so Mine does not expose them by default.

`PUT /api/invoices/{invoiceId}` accepts `assignedUserId`; send `null` to
unassign an invoice. The assignee must be a member of the invoice's company.
Existing super-admin requirements for invoice creation and API updates remain
in force. Invoice API responses include `createdBy` and `assignedUserId`.

Company administrators and super administrators can also use **Assigned user**
on the invoice detail page. Saving an assignment requires CSRF protection and
records an audit event. Assignment grants visibility only when the recipient's
role has Mine or All invoice access.
