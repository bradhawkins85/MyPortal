# SMB1001 Compliance

With Essential 8 being retired, MyPortal tracks company compliance against
**SMB1001**, the tiered cyber security certification standard for small and
medium businesses. The left menu entry formerly called **Compliance** is now
**SMB1001** and opens the SMB1001 dashboard at `/compliance`.

## Tiers

SMB1001 has five cumulative tiers. A company holds a tier only when every
control in that tier **and every lower tier** is *Compliant* or *Not
applicable*.

| Tier | Name | Certification |
| --- | --- | --- |
| 1 | Bronze | Self-attested by a director |
| 2 | Silver | Self-attested by a director |
| 3 | Gold | Self-attested by a director |
| 4 | Platinum | Independent verification audit |
| 5 | Diamond | Independent verification audit |

Controls are grouped into five domains: Technology management, Access
management, Backup and recovery, Policies, processes and plans, and Education
and training. Each control has a portal reference code (for example `TM-04` or
`AM-03`), a description and a **How it is checked** note describing the
evidence to look for.

> The control text in MyPortal summarises the standard. The SMB1001 standard
> is published by Dynamic Standards International and is revised
> periodically, so confirm the wording against the current edition before a
> director attests or an audit is booked.

## Using the dashboard

* **Tier achieved** shows the highest tier held, and how many controls remain
  for the next one.
* **Target tier** is the tier the company is working towards. Company
  administrators can change it, and progress is summarised against it.
  Sections above the target are marked *Beyond target*.
* Each control can be given a status, evidence, notes, an owner, a last
  reviewed date and a target date. Every change is recorded in the SMB1001
  audit trail and in the portal audit log.
* **Request technician help** raises a ticket (category `smb1001`) for a
  control that is not yet done. Only one open ticket per control and company is
  created.
* Filters narrow the list by text or status (including *Outstanding*).
* **Evidence files** can be uploaded against each control (up to 15 MB per
  file). Each upload becomes a new version and the newest is marked
  *Current*; administrators can delete a version, which makes the previous
  one current again. Files are stored privately and can only be downloaded
  by users with access to that company's SMB1001 compliance. File types that
  could run in the browser (for example HTML) are always downloaded rather
  than opened.
* **Get compliance help** links to the recommended product or service
  configured for a control (see below). It shows only while the control is
  not yet done.

## Automatically checked controls

Some controls are worked out from data already in the portal. When a check
decides the status, the status box is locked and a note under it explains the
result. The reported status is not written over the stored record, so manual
history and the audit trail are kept.

| Control | How it is checked |
| --- | --- |
| TM-01 Engage IT support | Companies flagged **VIP** are under a managed service agreement and are reported *Compliant*. Other (ad hoc) companies keep their manual status and can be sent a letter of engagement (below). |
| TM-03 Antivirus on every device | Every computer (desktop, laptop, server or virtual machine) in the asset register must report antivirus, either through a checked asset custom field named after an antivirus product (for example *Bitdefender Endpoint Security Tools*) or through Windows Defender reporting. All covered: *Compliant*. Any missing: *In progress*, naming the devices. |
| TM-07 Endpoint detection and response | As TM-03, but each computer must have a checked asset custom field whose name includes *Huntress*. |
| TM-08 Email authentication | *Compliant* when the Microsoft 365 best practice checks for SPF records, DKIM and DMARC records all pass. Otherwise the manual status is kept and the note lists each check's result. |

Archived assets, assets with **Archive Asset** checked, and devices such as
printers, network equipment and phones are not counted. When there are no
computers in the asset register, TM-03 and TM-07 keep their manual status.

### Letter of engagement (TM-01)

For companies that are not VIP, company administrators and super admins see
**Send letter of engagement** on TM-01 while it is not done. They choose a
company member to receive it; the letter is emailed, recorded in the TM-01
evidence and audit trail, and TM-01 is marked *Compliant*.

Super admins can change the wording under **Message templates**
(`/admin/message-templates`):

* `smb1001-engagement-letter` – the letter body. Variables:
  `{{ recipient.name }}`, `{{ recipient.email }}`, `{{ company.name }}`,
  `{{ sender.name }}`, `{{ sender.email }}` and `{{ letter.date }}`.
* `smb1001-engagement-letter-subject` – the email subject. Variables:
  `{{ company.name }}` and `{{ letter.date }}`.

## Recommended products and services

Super admins set a recommended product or service for each control under
**Marketing → SMB1001 help links** (`/admin/marketing/smb1001-help-links`).
Each control can link to a portal marketing page or to an external
`http(s)` URL; the external URL wins when both are set, and an unpublished
marketing page is not linked. These recommendations appear on the SMB1001
page and in the SMB1001 recommendations report section.

## Company reports

Two report sections are available under company report settings:

* **SMB1001 compliance** – tier achieved, target tier progress and per-tier
  counts (complete, in progress, non-compliant, not started). Its detailed
  view lists every control with status, review and target dates and the
  number of evidence files.
* **SMB1001 compliance recommendations** – outstanding controls up to the
  target tier (or the next tier, if the target is already met) with their
  recommended product or service.

The reporting catalogue also gains **Report - SMB1001 Compliance Progress**
and **Stat Strip - Company Overview - SMB1001**, and the default company
report layout now shows SMB1001 progress instead of Essential 8. Existing
saved layouts are not changed. The Essential 8 report sections are labelled
*(legacy)* and hidden when the `essential8` component is disabled.

Anyone with the **SMB1001** menu permission (`menu.compliance`, or the company
membership's *can view compliance* flag) can view the dashboard. Only company
administrators and super admins can change it.

## Converting Essential 8 progress

The first time a company opens the SMB1001 dashboard, its Essential 8
progress is converted into SMB1001 statuses where an Essential 8 maturity
level evidences the same practice:

| SMB1001 control | Essential 8 source |
| --- | --- |
| TM-04 Automatic security updates | Patch applications ML1 + Patch operating systems ML1 |
| TM-05 Remove unsupported software | Patch applications ML1 + Patch operating systems ML1 |
| TM-09 Restrict Office macros | Office macro settings ML1 |
| TM-10 Harden web browsers and applications | User application hardening ML1 |
| TM-11 Vulnerability scanning | Patch applications ML2 + Patch operating systems ML2 |
| TM-13 Application control | Application control ML2 |
| AM-03 MFA on email accounts | Multi-factor authentication ML1 |
| AM-05 Restrict administrator access | Restrict administrative privileges ML1 |
| AM-07 MFA on all business systems | Multi-factor authentication ML2 |
| AM-08 Privileged accounts isolated from risky activity | Restrict administrative privileges ML1 |
| AM-09 Phishing-resistant MFA | Multi-factor authentication ML3 |
| BR-01 Automated backups of important data | Regular backups ML1 |
| BR-02 Protected backups | Regular backups ML2 |
| BR-03 Test backup restores | Regular backups ML1 |

A control is carried over as *Compliant* when every listed Essential 8 level
is compliant, and as *In progress* when any of them has been started.
Converted controls are labelled **From Essential 8** and get a note naming the
source, so they can be reviewed against the SMB1001 check. Only controls that
have not been started are changed, so SMB1001 work is never overwritten.
Company administrators can run the conversion again with **Import Essential 8
progress**.

## Legacy Essential 8 records

Essential 8 data is not deleted. When a company has Essential 8 records (a
status other than *Not started*, evidence or notes), the SMB1001 dashboard
links to **Legacy Essential 8 records**
(`/compliance/essential8`), where the old controls, requirements, evidence and
exports remain available. The Essential 8 API and report sections are
unchanged.

## API

All endpoints are under `/api/smb1001`:

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/tiers` | List the five tiers |
| GET | `/controls?tier_level=` | List controls |
| GET | `/companies/{company_id}/overview` | Controls with status, tier progress and tier achieved |
| PATCH | `/companies/{company_id}/controls/{control_id}/compliance` | Set status, evidence, notes, owner and dates |
| GET | `/companies/{company_id}/controls/{control_id}/audit` | Change history for a control |
| PUT | `/companies/{company_id}/target-tier` | Set the target tier (1–5) |
| POST | `/companies/{company_id}/import-essential8` | Convert Essential 8 progress |
| GET | `/companies/{company_id}/controls/{control_id}/evidence` | List evidence versions for a control |
| POST | `/companies/{company_id}/controls/{control_id}/evidence` | Upload evidence (multipart: `title`, `evidence_file`, optional `description`) |
| GET | `/companies/{company_id}/evidence/{evidence_id}/download` | Download an evidence file |
| DELETE | `/companies/{company_id}/evidence/{evidence_id}` | Delete an evidence version |

## Deactivating

The `smb1001` component in `DISABLED_FEATURE_PACKS` hides the SMB1001 menu
entry, its pages and API, the SMB1001 help links admin page, and the SMB1001
report sections and reporting queries. See
[Component Deactivation](../getting-started/Component%20Deactivation.md).
