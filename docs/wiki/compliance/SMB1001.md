# SMB1001 Compliance

With Essential 8 being retired, MyPortal tracks company compliance against
**SMB1001**, the tiered cyber security certification standard for small and
medium businesses. The left menu entry formerly called **Compliance** is now
**SMB1001** and opens the SMB1001 dashboard at `/compliance`.

## Tiers

SMB1001 has five cumulative tiers. A company holds a tier only when every
control in that tier **and every lower tier** is *Compliant* or *Not
applicable*.

| Tier | Name | Certification |
| --- | --- | --- |
| 1 | Bronze | Self-attested by a director |
| 2 | Silver | Self-attested by a director |
| 3 | Gold | Self-attested by a director |
| 4 | Platinum | Independent verification audit |
| 5 | Diamond | Independent verification audit |

Controls are grouped into five domains: Technology management, Access
management, Backup and recovery, Policies, processes and plans, and Education
and training. Each control has a portal reference code (for example `TM-04` or
`AM-03`), a description and a **How it is checked** note describing the
evidence to look for.

> The control text in MyPortal summarises the standard. The SMB1001 standard
> is published by Dynamic Standards International and is revised
> periodically, so confirm the wording against the current edition before a
> director attests or an audit is booked.

## Using the dashboard

* **Tier achieved** shows the highest tier held, and how many controls remain
  for the next one.
* **Target tier** is the tier the company is working towards. Company
  administrators can change it, and progress is summarised against it.
  Sections above the target are marked *Beyond target*.
* Each control can be given a status, evidence, notes, an owner, a last
  reviewed date and a target date. Every change is recorded in the SMB1001
  audit trail and in the portal audit log.
* **Request technician help** raises a ticket (category `smb1001`) for a
  control that is not yet done. Only one open ticket per control and company is
  created.
* Filters narrow the list by text or status (including *Outstanding*).

Anyone with the **SMB1001** menu permission (`menu.compliance`, or the company
membership's *can view compliance* flag) can view the dashboard. Only company
administrators and super admins can change it.

## Converting Essential 8 progress

The first time a company opens the SMB1001 dashboard, its Essential 8
progress is converted into SMB1001 statuses where an Essential 8 maturity
level evidences the same practice:

| SMB1001 control | Essential 8 source |
| --- | --- |
| TM-04 Automatic security updates | Patch applications ML1 + Patch operating systems ML1 |
| TM-05 Remove unsupported software | Patch applications ML1 + Patch operating systems ML1 |
| TM-09 Restrict Office macros | Office macro settings ML1 |
| TM-10 Harden web browsers and applications | User application hardening ML1 |
| TM-11 Vulnerability scanning | Patch applications ML2 + Patch operating systems ML2 |
| TM-13 Application control | Application control ML2 |
| AM-03 MFA on email accounts | Multi-factor authentication ML1 |
| AM-05 Restrict administrator access | Restrict administrative privileges ML1 |
| AM-07 MFA on all business systems | Multi-factor authentication ML2 |
| AM-08 Privileged accounts isolated from risky activity | Restrict administrative privileges ML1 |
| AM-09 Phishing-resistant MFA | Multi-factor authentication ML3 |
| BR-01 Automated backups of important data | Regular backups ML1 |
| BR-02 Protected backups | Regular backups ML2 |
| BR-03 Test backup restores | Regular backups ML1 |

A control is carried over as *Compliant* when every listed Essential 8 level
is compliant, and as *In progress* when any of them has been started.
Converted controls are labelled **From Essential 8** and get a note naming the
source, so they can be reviewed against the SMB1001 check. Only controls that
have not been started are changed, so SMB1001 work is never overwritten.
Company administrators can run the conversion again with **Import Essential 8
progress**.

## Legacy Essential 8 records

Essential 8 data is not deleted. When a company has Essential 8 records, the
SMB1001 dashboard links to **Legacy Essential 8 records**
(`/compliance/essential8`), where the old controls, requirements, evidence and
exports remain available. The Essential 8 API and report sections are
unchanged.

## API

All endpoints are under `/api/smb1001`:

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/tiers` | List the five tiers |
| GET | `/controls?tier_level=` | List controls |
| GET | `/companies/{company_id}/overview` | Controls with status, tier progress and tier achieved |
| PATCH | `/companies/{company_id}/controls/{control_id}/compliance` | Set status, evidence, notes, owner and dates |
| GET | `/companies/{company_id}/controls/{control_id}/audit` | Change history for a control |
| PUT | `/companies/{company_id}/target-tier` | Set the target tier (1–5) |
| POST | `/companies/{company_id}/import-essential8` | Convert Essential 8 progress |

## Deactivating

The `smb1001` component in `DISABLED_FEATURE_PACKS` hides the SMB1001 menu
entry and its pages and API. See
[Component Deactivation](../getting-started/Component%20Deactivation.md).
